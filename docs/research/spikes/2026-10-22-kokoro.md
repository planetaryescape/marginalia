# Kokoro through OpenRouter: voices, size and latency

Run on 2026-10-22 against the owner's OpenRouter key, from a Mac in the UK with `curl` and Bun. This covers the Kokoro parts of S1, S2 and S3 in [the Listen blueprint](../../listen/blueprint/08-open-questions.md). The samples stayed outside the repo.

## The request works as the blueprint wrote it, plus price routing

```json
{
  "model": "hexgrad/kokoro-82m",
  "input": "<text>",
  "voice": "bf_emma",
  "response_format": "mp3",
  "provider": { "sort": "price", "data_collection": "deny" }
}
```

All 29 requests returned 200 with `content-type: audio/mpeg` and an `x-generation-id` header.

Kokoro has two providers on OpenRouter: DeepInfra at $0.00000062 a character and Together at $0.000004, 6.5 times more (`GET /api/v1/models/hexgrad/kokoro-82m/endpoints`). `sort: "price"` routed to DeepInfra: the generation record for a 50-character probe shows `provider_name: DeepInfra` and `total_cost: 0.000031`. Without it, OpenRouter's load balancing could send some requests to Together, and the "about 3 cents an hour" figure would drift. Both providers list `supported_parameters: []`, so Kokoro takes no `instructions` and no `speed`.

`data_collection: "deny"` left a provider, so private routing doesn't cost Kokoro anything.

OpenRouter lists 50+ Kokoro voices in `supported_voices`. The eight sampled were `af_heart`, `af_bella`, `am_michael`, `am_fenrir`, `bf_emma`, `bf_isabella`, `bm_george` and `bm_fable`.

## A clip is about 0.5 MB per 1,000 characters (S2)

Every voice returned 64 kbps mono MP3 at 24 kHz. Measured over 29 clips by decoding them with `ffmpeg -f null`:

| | Per 1,000 characters |
|---|---|
| Size | 0.46–0.70 MB (prose about 0.5; the numbers passage, which expands when spoken, up to 0.7) |
| Speech | 64–95 s (prose about 68 s) |
| Speaking rate | 13–15.5 characters a second for prose; 10.5–12 for the numbers passage |

A 2,000-character clip is about 1 MB and 140 s, well inside the 16 MiB a Convex action can return.

The MP3 carries no accurate duration header. ffprobe's header estimate was about 28% too long (46.1 s against 36.1 s decoded for the same clip). Browsers estimate `audio.duration` the same way, so the player mustn't rely on it before `ended`.

## A short first clip is needed to start within 2 seconds (S3)

Time from sending the request to having the whole body, from the UK:

| Characters | Time |
|---|---|
| 300–310 | 0.9–1.4 s |
| 430–550 | 1.1–2.7 s |
| about 2,000 | 3.8–4.2 s |
| about 3,900 | 6.0 s, not truncated |

A typical paragraph can take more than 2 seconds, and a long one takes 4. So the first clip of a listen packs only the starting paragraph's leading sentences, up to 300 characters, and the rest of that paragraph follows as the next clip (D-TTS-023). From the second clip on, the lead of three clips hides synthesis completely: each clip plays for 20 seconds or more and takes a few seconds to make.

These times are from `curl` on a home connection. The same request from a Convex action in `eu-west-1` should be no slower, which rung 1's deployed demo checks.

## Kokoro reads numbers well and spells unit abbreviations out (S1)

A transcript of the numbers passage in `af_heart`, made with Gemini 3.8 Flash, shows the following:

- Read as intended: "25 December 2021" as "twenty-five December twenty twenty-one", "$10 billion" as "ten billion dollars", "−233 °C" as "minus two hundred thirty-three degrees C", and NASA as a word.
- Spelled out: ESA and CSA as letters, which is right.
- Spelled out letter by letter: "6.5 m" became "six point five M", "km" became "K-M" and "bn" became "B-N".

Rung 1 leaves unit abbreviations as they are. Expanding them needs context ("5 m" can be metres, minutes or million), and the owner judges it by ear when picking the voice.

That transcript has every sentence of the passage, in order. Only one clip was transcribed; the others were checked by their decoded length, which tracks their character count. Kokoro is a plain text-to-speech model with no prompt, so it has no way to add or reword anything the way a prompted model can.
